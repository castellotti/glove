- `gh` and git's network commands (`git push`/`fetch`/`pull`/`clone`/`ls-remote`) work from shell commands: they are relayed to a sidecar that holds this session's GitHub token. You never see the token, and no other shell command has network. Remotes must be `https://github.com/OWNER/REPO(.git)` (switch an SSH remote with `git remote set-url origin https://github.com/OWNER/REPO.git`).
- Relayed commands get no stdin: write a body to a file under /work and pass `--body-file <file>`. File and directory arguments must be under /work. `gh api` is GET only (no GraphQL; fields need `-X GET`). `gh auth`, `extension`, `alias`, `config`, `codespace`, `secret`, `variable`, `ssh-key` and `gpg-key` are never relayed, so `gh auth token` is refused; other gh commands run only if the session allows them. Instead of `gh pr checkout <n>`, run `git fetch origin pull/<n>/head:<branch>` and then `git checkout <branch>`.
